# правоХ

Telegram-бот и Mini App для граждан и студентов юридических вузов. Размещён в Н12/правоХ отдельно от Valevo. Docker Compose проект называется pravox; его сеть, контейнеры и тома отделены от остальных проектов. Существующие файлы Valevo не изменены.

## Первый запуск

В терминале сервера, из корня клона репозитория valevo:

```bash
git pull --ff-only
cd 'Н12/правоХ'
python3 deploy/configure.py --local
bash deploy/start.sh
```

Нужны Docker Engine с Compose и Python 3. При настройке введите токен именно бота правоХ; ввод скрыт. Админ 6021377014 и канал @pravoXru уже заданы. Добавьте бота администратором канала для проверки подписки. API-ключ ИИ не нужен. Секреты сохраняются только на сервере в infra/.env с правами 600, файл исключён из Git. Не копируйте настройки другого проекта.

Установщик собирает приложение, проверяет Telegram/канал и отсутствие занятого webhook, запускает Ollama, загружает qwen3:4b, делает реальный тест ИИ, затем включает web, worker и bot. Повторный запуск допустим; существующая конфигурация не перезаписывается. Ошибки останавливают установку. Процесс загрузки модели может занять несколько минут.

Для модели предусмотрен запас: не менее 6 ГиБ доступной RAM и 10 ГиБ свободного места в Docker-хранилище. Ollama ограничен 5 ГиБ RAM и двумя ядрами CPU, один запрос одновременно. Проверка памяти выполняется до запуска модели. Если ресурсов недостаточно, установщик сообщит об этом; характеристики сервера пока неизвестны.

## Обновление

Из папки Н12/правоХ после успешного первого запуска:

```bash
git pull --ff-only
docker compose -f infra/docker-compose.yml --env-file infra/.env up -d --build web worker bot
```

Запуск с перечисленными сервисами обновляет только правоХ. Ollama продолжает работать после первого запуска. Если нужно вновь поднять и модель:

```bash
docker compose -f infra/docker-compose.yml --env-file infra/.env up -d ollama
docker compose -f infra/docker-compose.yml --env-file infra/.env up -d --build web worker bot
```

Миграции Prisma и @zaa4eem/api не используются. Собственная SQLite-база создаётся приложением в томе pravox_app_data.

## Проверка и управление

```bash
docker compose -f infra/docker-compose.yml --env-file infra/.env ps
docker compose -f infra/docker-compose.yml --env-file infra/.env logs --tail=100 bot worker web ollama
curl --fail http://127.0.0.1:8095/pravoXru/healthz
```

В Telegram: /start, вопрос, /app для приложения, /admin для статистики. Первые три успешных юридических запроса без подписки, затем проверка @pravoXru. Администратор освобождён от лимита. История общая для чата и Mini App. Команды и технические ошибки не расходуют запросы. Уточняющие ответы расходуют запрос.

Остановить только правоХ:

```bash
docker compose -f infra/docker-compose.yml --env-file infra/.env stop
```

Не используйте down -v: это удаляет базу и модель.

## Подключение Mini App

Целевой адрес: https://zaa4eem.ru/pravoXru/. Обычный чат работает без настройки этого маршрута, но Mini App требует HTTPS. Web слушает 127.0.0.1:8095 и не занимает 80/443. Если порт занят, задайте APP_PORT в infra/.env и тот же порт в прокси.

Если существующий Nginx работает непосредственно на сервере, добавьте содержимое deploy/nginx-pravox.conf внутрь действующего HTTPS server для zaa4eem.ru. Сначала сохраните копию действующего конфига, затем nginx -t и systemctl reload nginx. Не заменяйте весь конфиг сайта. Если Nginx находится в контейнере, его localhost относится к самому контейнеру: потребуется отдельное подключение к правоХ через сеть Docker. Конфигурации сайта в этом репозитории нет, поэтому окончательный маршрут здесь не применялся. Для Apache/Caddy используйте соответствующие настройки, не команды Nginx.

## Переключение на GigaChat

Локальный Qwen не подходит для данного VPS: доступно около 715 МБ памяти, а модель требует существенно больше. Для GigaChat локальная модель и контейнер Ollama не запускаются.

1. Создайте проект в [GigaChat API Studio](https://developers.sber.ru/docs/ru/gigachat/quickstart/ind-using-api) и в «Настройки API» получите **Authorization Key**. Сохраните его: в личном кабинете он показывается один раз. Это не токен Telegram и его нельзя публиковать.
2. После получения ключа в папке проекта выполните `python3 deploy/switch_to_gigachat.py`, вставьте ключ в скрытое поле и оставьте scope `GIGACHAT_API_PERS` для физлица.
3. Запустите `bash deploy/start.sh`.

Скрипт получает короткоживущий Access token через серверный OAuth и обновляет его автоматически. Ключ сохраняется только в `infra/.env`; предыдущее локальное окружение будет сохранено в `infra/.env.before-gigachat`. Оба файла исключены из Git. GigaChat тарифицирует запрос и ответ в токенах; количество и остаток отображаются в кабинете GigaChat.

Первый адаптер GigaChat не выполняет веб-поиск и не выдаёт искусственные ссылки: каждый ответ содержит предупреждение о необходимости проверить актуальную редакцию и официальные источники. Для публичной юридической версии с ссылками нужен отдельный законный источник актуальных актов или совместимый поиск.

## ИИ и данные

Тестовый Qwen3 4B работает на сервере без оплаты API. Это настройка готовой открытой модели, не обучение новой нейросети. В локальном режиме нет поиска и актуальной базы законов; каждый ответ явно помечен как непроверенный тестовый. Юридическая точность и скорость на реальном сервере пока не оценивались. Модель нельзя считать полной базой законодательства РФ.

Сохранён отдельный адаптер Responses API с web_search и обязательными официальными источниками. Он требует совместимого провайдера, модели и API-ключа. Для него задайте AI_BACKEND=responses и остальные поля через настройку без --local; существующий infra/.env изменяется вручную.

История хранится 90 дней, ежедневные копии SQLite на том же сервере — 7 дней. /delete удаляет тексты истории, сохраняя статистику и счётчик. Копии на одном сервере не защищают от его потери. Данные Telegram обрабатываются отдельно. Админ видит статистику, пользователей и метаданные запросов, без текстов переписок; доступен CSV.
