# VALEVO — Mini App: бронирования

## Текущая версия

Интерфейс в стиле ТВ-борда, «Общий зачёт», «Карточка пилота». Три серверные роли: пользователь, админ, супер-админ. Все роли сохраняют обычные пользовательские функции.

Бронирование: выбор даты/времени или сначала мест, схема шести симуляторов, 30/60/90/120/180 минут, до трёх мест одного типа. Тарифы: статика700 ₽/час, подвижка1000 ₽/час. Бронь создаётся в общей базе с ботом и ожидает супер-администратора. Подтверждение использует YCLIENTS; отмена удаляет созданные записи. Проверки доступности выполняются повторно при создании и подтверждении.

Статистика супер-администратора: число подтверждённых броней, место-часы, стоимость по сохранённому тарифу, расчётные10% разработчику, доля клуба90%, график по московским датам заезда, фильтр бот/Mini App. Отменённые и неподтверждённые заявки исключены. Это расчёт стоимости броней, не бухгалтерская выручка. Оплат, возвратов, выплат и их API в этой версии нет.

Профиль, результаты, зачёт, рефералы и рулетка используют существующие сервисы бота. Реализованы изменение имени, просмотр результатов, ввод времени админом, поиск пилота, управление трассами и эталонами супер-администратором. Повторная отправка брони и результата защищена ключами запроса.

## Запуск на существующей установке

Пользователь запускает на сервере через Docker. Используйте существующий `docker-compose.yml` в корне `Н12`, как в репозитории. Контейнер `valevo-bot` запускает `bash scripts/start.sh` → `main.py`, контейнер `valevo-webapp` — `webapp_server.py`. База и `.env` общие. Файлы Compose/Dockerfile/точки входа совпадают с upstream. Подтверждённый порт пользователя — `127.0.0.1:8020` →8080; сохраняйте `WEBAPP_PORT=8020`. Подробные команды: `DOCKER_START.md`.

1. Сделайте SQLite backup работающей базы через SQLite backup API; сохраните текущую версию приложения и `.env`. Не копируйте только файл `.db` при активной записи в WAL.
2. Обновите файлы каталога `Н12`, сохранив существующие `.env`, `data`, `logs`, `backups` и базу. Архив этой версии не содержит пользовательской базы и секретов.
3. В существующем `.env` проверьте `BOT_TOKEN`, `ADMIN_IDS`, `SUPER_ADMIN_IDS`, `YCLIENTS_COMPANY_ID`, `YCLIENTS_PARTNER_TOKEN`, `YCLIENTS_USER_TOKEN`. Оба процесса должны использовать один `DB_NAME`.
4. Укажите `WEBAPP_URL=https://ваш-домен` и направьте HTTPS reverse proxy на веб-приложение. В Docker Compose порт уже ограничен `127.0.0.1`. Кнопка Mini App появляется в меню бота при заполненном `WEBAPP_URL`.
5. Из каталога проекта выполните `docker compose up -d --build`. Альтернатива: установите `requirements.txt` в отдельное окружение, запустите `python main.py` и `python webapp_server.py`.
6. Проверьте `/api/health`, открытие из Telegram для всех трёх ролей и одну согласованную тестовую бронь с подтверждением и отменой. Автоматические тесты не обращаются к реальному Telegram/YCLIENTS.

При старте добавляются колонки источника, тарифа, стоимости, процента и ключа запроса, таблица уведомлений. Старые записи не удаляются. Старые брони без сохранённого тарифа включаются в количество/часы, но отдельно отмечаются и не включаются в денежную оценку.

Уведомления о заявках из Mini App и их статусах идут через очередь в общей базе; бот обрабатывает её каждые30секунд. При сбое Telegram доставка повторяется. После аварии между отправкой сообщения и фиксацией доставки возможен повтор сообщения — Telegram не даёт ключ идемпотентности для отправки.

## Проверка перед реальным использованием

Из каталога `Н12`: установите `pytest`, `httpx`, `tzdata` в тестовое окружение и выполните `python -m pytest tests -q`; для JS — `node --check webapp/static/js/app.js`. Полный сценарий проверяется в `tests/test_miniapp_journey.py`: заявка, повтор, подтверждение, статистика и отмена без платёжных операций.

Проверьте сопоставление `BOOKING_PLACES`, staff_id и service_id в `handlers/booking.py` с действующим YCLIENTS. Исходный репозиторий задаёт одинаковый service_id для статики и подвижки; его соответствие реальной конфигурации не проверялось.

При статусе `reconciliation_required` автоматическое повторное создание заблокировано: сначала сверьте внешние записи по `api_id=valevo-<бронь>-<место>`. При `cancellation_failed` место сохраняется занятым до устранения ошибки. Не сбрасывайте статус вручную, не проверив фактическое состояние YCLIENTS.

## Что ещё не является полным переносом бота

Через переход в бот остаются отправка результата с фото/видео, модерация, поддержка, редактирование отдельных данных пилота и бонусов, рассылки и закрытие Week CUP. Существующая рулетка перенесена через API, но её исходная логика внешнего списания бонусов требует отдельной проверки надёжности. Не считать эту сборку полностью завершённым production-аудитом всего старого бота.

Реальное развёртывание, проверка HTTPS и приёмка с YCLIENTS ещё не выполнялись: рабочие доступы и сервер в этой сессии не использовались. При откате восстановите предыдущие файлы; перед восстановлением базы остановите оба процесса и используйте согласованную резервную копию.
