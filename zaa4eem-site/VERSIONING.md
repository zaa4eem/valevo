# Версия сборки

Формат: `MAJOR.FEATURES.BUILD` (например `1.9.16`).

- **MAJOR** — глобальная версия платформы. Меняется только при полном
  релонче продукта. Сейчас: `1`.
- **FEATURES** — сколько крупных новых возможностей выпущено с начала
  MAJOR-версии. +1 только за реально новую функцию (не за багфикс, не за
  визуальный редизайн существующей функции, не за доводку/интеграцию уже
  посчитанной ранее фичи). Никогда не уменьшается, не сбрасывается.
- **BUILD** — сквозной номер сборки. +1 на каждый релиз без исключений
  (фича это или фикс), никогда не сбрасывается.

Схема принята 2026-09-04. История сборок 1.0.1–1.0.16 (в git-логе и
коммит-мессаджах) задним числом не переписывается — считаем правильно
только начиная с этого момента. Реальное текущее состояние прямо
сейчас: **1.10.21**.

## Что уже засчитано в FEATURES (10)

1. Посты: лайки, комментарии, публикация с ограничением раз в 12ч (1.0.1)
2. Подписки между пользователями (1.0.3)
3. Admin-панель «Пользователи» (мут/бан/восстановить) (1.0.4)
4. Редактирование/удаление своих постов и комментариев (1.0.7)
5. Восстановление пароля по почте (1.0.8)
6. Поиск по профилям/постам/идеям (1.0.10)
7. Списки подписчиков/подписок + Telegram-уведомления + haptics (1.0.11)
8. Картинки в постах (1.0.14)
9. Premium (анимированный ник, значок, рамка аватара) (1.0.15)
10. Самостоятельная настройка Premium-стиля в /settings (1.10.19)

Не засчитаны как отдельные функции: багфиксы (1.0.2, 1.0.5, 1.0.9,
1.9.17, 1.9.18, 1.10.20), диагностика/логирование без функционального
изменения (1.10.21), инфраструктура/CI (1.0.9), редизайн без новой
функциональности (1.0.6, 1.0.12 частично, 1.0.13), доводка уже
посчитанной фичи (1.0.16 — доинтеграция Premium из 1.0.15, а не новая
функция).

## Следующий релиз

- Только фикс/полировка/доводка → BUILD +1, FEATURES не меняется
  (например `1.10.22`).
- Добавлена новая крупная функция → FEATURES +1, BUILD +1
  (например `1.11.22`).

## Формат объявления сборки

```
Сборка X.Y.Z:
- Новая фича 1
- Новая фича 2

- Исправлена проблема, когда ...
- Исправлена проблема, когда ...
```

Сначала новые возможности, пустая строка, затем исправления — без
отдельного заголовка «Исправлено», просто следующим блоком.
